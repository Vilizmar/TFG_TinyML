Hoy hemos intentado fusionar de verdad el boceto de Arduino de EdgeImpulse, con el que se detectan los distintos objetos, y el sketch de mqtt para enviar datos pub vía wifi.

Como ya comentamos en el diario anterior, antes de nada había que instalar la biblioteca de Arduino PubSubClient para poder utilizar Mqtt dentro del IDE.

Una vez hecho esto hemos cambiado unos parámetros dentro del mosquitto.conf para que este pudiese recibir datos de otros dispositivos:
	-> listener 1883
	-> allow_anonymous true
	-> https://www.youtube.com/watch?v=G_Xj6II8waY (Aquí lo explica + Firewall de Windows)

Sin embargo, esto ha resultado ser inútil porque utilizaremos bróker.hivemq.com en vez de las direcciones IPv4 para ahorrarnos dolores de cabeza en el futuro.

Dentro del .ino hemos tenido que indicar los códigos ssid, contraseña y server del Wifi para poder llevar a cabo la conexión.

Ahora mismo el código de wifi se ha modificado para solucionar varios problemas (antes, se inicializaba antes la cámara que el malloc donde se guardaría por lo que daba un error gordo).

Actualmente la portenta H7 da error incluso con el código original de detección de objetos, sospecho que ocurre porque se ha quedado en memoria basura de las pruebas anteriores.

Puede ocurrir el error porque hay librerías incompatibles??


SOLUCIÓN: Parece que el problema ocurría por fragmentación de memoria. El modelo de IA para detección de objetos es bastante grande para la RAM de un microcontrolador y el WIFI y PubSubClient necesitan asignar memoria dinámicamente para poder conectarse a los sockets + manejar los buffers de los mensajes MQTT. Vamos que entraban en conflicto y empezaban a leer zonas prohibidas de memoria o directamente StackOverflow por lo que la portenta empezaba a parpadear en rojo (se bloqueaba para evitar problemas de hardware).



Foro con la solución al problema de la fragmentación: https://forum.edgeimpulse.com/t/failed-to-allocate-tflite-arena-error-code-1-on-portenta/4777


Página para probar conexiones wifi mqtt: https://www.hivemq.com/demos/websocket-client/


Para que la conexión MQTT funcione con la portenta H7 y usando el hotspot del móvil con datos móviles se debe desconectar la conexión wifi del dispositivo y forzar el ancho de banda de 2,4 GHz. Si no, la portenta se quedará atascada en un estado de continuo intento de conexión.
